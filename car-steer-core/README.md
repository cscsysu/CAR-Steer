# CAR-Steer

Core inference implementation for **Rescuing Internally Recalled Facts under
Knowledge Conflict via Curvature-Triggered Residual Steering**.

CAR-Steer performs a single, gated residual update during prefill and uses a
context-matched logit bias for up to three answer tokens. Model weights remain
fixed. Generation takes a context and a question; it does not take a gold answer.

## Contents

- Causal curvature monitoring and historical candidate selection.
- Vocabulary-centered token directions and norm-scaled, gated residual steering.
- Exact token-ID context matching and attention-based span selection.
- Greedy generation with the modified prefill's KV cache.
- Model-specific paper presets, a JSONL command, and offline correctness tests.

This is a reference implementation of the core method. Benchmark datasets,
pretrained weights, comparator implementations, and the complete experimental
pipeline are separate from this release. No reported benchmark scores are
embedded in the code or generated by its tests.

## Installation

Use Python 3.10--3.12. Install a PyTorch build appropriate for your CPU/CUDA
environment, then install this package:

```bash
python -m pip install -e ".[test]"
```

The Hugging Face integration is pinned to **Transformers 4.51.2**. The supported
PyTorch range is 2.4--2.6. The manuscript specifies PyTorch 2.4.0 with CUDA 12.4;
the included local correctness tests were run with PyTorch 2.6.0 on CPU. They use
actual Qwen3, Llama, and Mistral decoder classes with tiny random weights, without
downloading models. They validate implementation behavior, not benchmark EM.

## Quick start

```bash
car-steer --model Qwen/Qwen3-8B --preset qwen3-8b \
  --input examples/questions.jsonl --output outputs/predictions.jsonl \
  --device cuda --dtype bfloat16
```

The command is also available as `python -m car_steer.cli`. For downloaded
weights, pass their directory to `--model` and add `--local-files-only`.
For remote weights, `--revision` accepts a commit ID to fix the model revision.
Model access and downloaded weights remain subject to the model provider's terms.

Each input line contains `context`, `question`, and an optional `id`. The supplied
examples are synthetic. Each output contains raw answer text, generated token
IDs, configuration, and the intervention trace. The command refuses to overwrite
an existing output file.

### Python API

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from car_steer import CARSteer, SteeringConfig

model_id = "Qwen/Qwen3-8B"
tokenizer = AutoTokenizer.from_pretrained(model_id, use_fast=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    attn_implementation="eager",
).to("cuda")

runner = CARSteer(model, tokenizer, SteeringConfig.preset("qwen3-8b"))
result = runner.generate(
    context="The city of Luma opened its observatory in 1998. Its director was Mira Sen.",
    question="Who was the director?",
)
print(result.text)
print(result.prefill)
```

Construct the wrapper after placing the model on its final device and dtype.
Recreate it after changing the model's weights. One wrapper handles one request
at a time; do not run another inference concurrently on the same model instance.

### Paper presets

| Preset | Model family | Blocks | Curvature centers | Candidate cap | Threshold |
|---|---|---:|---|---:|---:|
| `qwen3-8b` | Qwen3-8B | 36 | 3--31 | 28 | 0.385 |
| `llama-3.1-8b` | Llama-3.1-8B-Instruct | 32 | 3--31 | 25 | 0.412 |
| `mistral-7b` | Mistral-7B-Instruct-v0.3 | 32 | 3--31 | 25 | 0.368 |

All use `alpha=1.0`, `initial_bias=2.0`, `bias_decay=0.5`, and
`max_new_tokens=32`. The JSON equivalents are in `configs/` and can be supplied
with `--config`. Presets validate the loaded model's family and depth.

For another model size within a supported family, provide an explicit
`SteeringConfig(threshold=..., center_end=...)` with separately calibrated
settings. Its default end is `L-1`; the Qwen3-8B cutoff of 31 is a paper preset,
not a rule inferred for every Qwen3 model.

## Method correspondence

All trace layer numbers are **1-based decoder-block numbers**; embeddings do not
count as a block. `model.model.layers[i]` produces `h_(i+1)`.

| Manuscript component | Implementation |
|---|---|
| Eq. (1), center-indexed curvature | `geometry.curvature` |
| Eq. (2), observed historical probability peak | `geometry.HistoricalPeak`, `hooks.PrefillMonitor` |
| Eq. (3), projection-ratio gate | `geometry.gate_multiplier` |
| Centered direction and norm-scaled update | `geometry.vocabulary_mean`, `geometry.residual_update` |
| Sec. 4.3 / App. B.6, context-prefix bias | `spans.select_span`, `spans.ShortSpanBias` |
| App. A.2, causal hook and cached decoding | `hooks.PrefillMonitor`, `generation.CARSteer` |

### Prefill timing

1. A block hook observes the complete post-MLP residual output at the last prompt
   position. Only the most recent three vectors are retained for curvature.
2. Once block `l+1` completes, compute `kappa_l` from `h_(l-1), h_l, h_(l+1)`.
   Curvature is calculated in float64. A displacement norm below `1e-6` gives zero.
3. At the first **strict** crossing `kappa_l > threshold`, select the highest
   projected token probability among layers `1..min(l, floor(0.8L))`.
   Projection uses the model's final output normalization and LM head. Equal
   probabilities keep the shallower layer; equal token logits choose the smaller ID.
4. Evaluate the gate on raw `h_(l+1)` and the vocabulary-centered target vector.
   Add the norm-scaled update to **only the last prompt position** and return the
   modified block output before downstream blocks execute. A closed gate ends
   the search; the method does not wait for another crossing.
5. Remove all hooks after prefill. Later tokens use the resulting KV cache with
   no further residual injection or curvature scan.

For Qwen3-8B the latest injection is at block 32, leaving blocks 33--36 downstream.
For the 32-block presets, center 31 is eligible and updates block 32. An output
update cannot retroactively alter caches in the injection block or earlier
blocks. It can affect downstream caches; a final-block update affects first-token
logits without rewriting preceding caches.

### Gate and output bias

For cosine alignment `r`, the multipliers on `alpha` are:

| Interval | Multiplier |
|---|---:|
| `r < 0` | 0 |
| `0 <= r < 0.001` | 2 |
| `0.001 <= r < 0.01` | 1 |
| `0.01 <= r < 0.1` | 0.3 |
| `r >= 0.1` | 0 |

No crossing or a closed gate disables both components. A zero-norm state or
direction also disables intervention and is recorded in the trace.

On an active example, answer step 0 adds `+2.0` to the target token alone. If that
token is emitted, exact token-ID matching searches the **context portion of the
actual prompt tokenization**, preserving leading-space distinctions. Each matching
occurrence supplies its longest contiguous span of up to ten tokens before a
stop token. Multiple spans are ranked by mean penultimate-block attention from
the last prompt query, averaged over all query heads and then span tokens. Ties
choose the earliest context character offset.

The selected span's second and third tokens receive `+1.0` and `+0.5`. Bias ends
on a post-bias greedy mismatch, no context match, span exhaustion, punctuation,
whitespace/newline-only tokens, or EOS, and always ends after three tokens. Stop
IDs are built using decoded token strings and Python's `string.punctuation`.
Thus punctuation within numbers or hyphenated names can end bias early.
Ending **bias** does not end **generation**: only EOS or the generation-length
limit does that.

The prompt is a plain string; the runner applies no chat template:

```text
Context: {context}
Question: {question}
Answer with the shortest span from the context:
```

## Auditing and component controls

`result.prefill` records the observed curvatures, trigger center, injection block,
candidate layer/token/probability, gate alignment, effective strength, and whether
the residual was changed. `result.bias_steps` records the expected token, emitted
token, applied bias, and stopping reason at every answer step.

Use `SteeringConfig.preset("qwen3-8b", bias_enabled=False)` for residual steering
alone. `residual_enabled=False` leaves the gate/target scan active but suppresses
the residual update, allowing bias-only inference. Setting both flags to `False`
leaves generation unmodified while still recording the scan. These switches
execute their respective trajectories; they do not automatically freeze a target
or gate from a separate full-method run for matched counterfactual experiments.

## Tests

```bash
python -m pytest
```

Tests cover gate boundaries, strict thresholding, degenerate displacements,
historical selection, context-only matching, leading-space distinctions, span
scoring, permanent bias stopping, and hook cleanup. Integration tests run actual
HF Qwen3/Llama/Mistral classes, compare inactive behavior to HF greedy generation,
and compare active logits and per-layer KV caches with an explicit manual update.

## Execution scope

The core runner supports one unpadded example, greedy decoding, a fast tokenizer,
floating-point weights, and a single CPU or CUDA device. It rejects unsupported
architectures, mismatched presets, quantized models, and model sharding. Contexts
are not silently truncated; the prompt and requested generation must fit the
configured context window.

Use `attn_implementation="eager"` so the span scorer can read attention weights.
The code retains only the penultimate layer's last-query attention row, but eager
attention still computes its full attention matrices transiently. Logit-lens
projections and span matching also incur computation. Runtime, GPU memory, and
task accuracy need measurement with the chosen pretrained weights and inputs.
